Problem — a run is assembled from three modules that each hold part of the protocol, so nobody owns stopping, a connection that dies without a terminal frame, or a malformed frame; leaving the Console mid-run keeps the fetch — and the User's key — paying for output nobody reads until the server gives up.

Solution — one Run module: start, progress, stop on the interface; the abort signal, frame parsing, in-stream 401 handling and close-without-terminal absorbed into the implementation; the Console — not a lib hook — decides where a failed run goes.

  • abort becomes one implementation detail
  • tests cross the interface with a fake transport
  • 401 handled once, not twice
  • close-without-terminal has an owner
  • a lib stops owning a route
  • leverage: one interface, every future hardening
One-shot, no Run id, no reconnection stays true (ADR-0007): a Stop button is the client pulling the abort the server already implements — nothing reverses.

Top recommendation

Give the Run one module

Deepest payoff at the seam the Console was just rebuilt around, and the gaps are user-visible today: no Stop, an abandoned visit keeps the User's key paying, and a dropped connection strands Running… forever — Give the SSE wire an owner rides along, since the same frames get pinned and the dead ones deleted.

Cheapest strong win if the mood is smaller: retire PUT — zero callers, pure deletion and consolidation.
